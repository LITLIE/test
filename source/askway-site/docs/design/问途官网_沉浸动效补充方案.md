# 问途官网：沉浸动效补充方案

日期：2026-11-24，Asia/Hong_Kong。状态：官网规划的补充设计，尚未进入动画代码实现。用户已提出加入更高级动画、提升沉浸感。本方案保持“品牌形象与合作价值”的目标，并升级原规划中较轻的动效方案。

关联主规划：[官网前端规划](D:/AAA大三上/软件工程/问途立项/dev/docs/official-site-2026-11-24/官网前端规划.md)。本补充说明保存于本轮新指定的工作区，原项目文件未在本轮修改。

## 1. 动效主线

**让一条路线，带访客看懂问途。**

以“海岸城市 × 可信科技”为视觉基础，让路线成为贯穿页面的共享视觉线索：首屏海岸上的光点形成路线，路线在产品章节连接条件与景点，在手机场景中成为执行进度，最后延伸到合作邀请。

整体观感采用“电影感首屏、随滚动展开的产品叙事、精细的交互反馈”。两处重点场景承担沉浸感，其余内容保持清晰的阅读节奏。品牌目标、正式页面范围与真实产品能力表述沿用主规划。

## 2. 动效分镜与优先级

| 场景 | 动效设计 | 用户能够理解的内容 | 首版优先级 |
|---|---|---|---|
| 首屏 · 海岸启幕 | 海岸前后景以小幅速度差形成景深；柔和光影掠过画面；标题按行轻微入场；路线从一个光点展开 | 问途的城市探索气质与品牌记忆 | P0 |
| 产品 · 一段旅程的形成 | 桌面端设置一处粘性展示舞台；随正常滚动依次呈现“商讨—规划—调整—执行”，路线节点、说明和产品画面同步更新 | 产品如何把偏好衔接为可执行的行程 | P0 |
| 跨端 · 从桌面到手机 | 共享的路线图形在两个展示区域间平滑转移，桌面与手机各自保持真实界面比例；场景切换可加入轻微透视 | 电脑规划与手机现场执行的连续性 | P0 |
| 珠海 · 路线与城市 | 用户切换场景节点时，路线逐段描绘，场景照片和文字说明相应更新 | 行程中的节点、顺序与城市体验 | P0 |
| 导航 · 进入产品或合作页 | 对一个确定的共享画面做位置与尺寸过渡，配合新页面短暂入场 | 页面间的空间连续性与当前位置 | P1 |
| 合作 · 旅程的延伸 | 路线在合作区收束到一个节点，再延伸为简洁的合作方向结构 | 从现有产品能力进入可讨论的合作场景 | P1 |
| 微交互 · 按钮与产品展示 | 按钮箭头移动、边界与颜色反馈；桌面产品展示轻微倾斜；选中阶段保持明确标记 | 当前动作、选择状态与操作反馈 | P0 |

P0 先做成完整、可验证的视觉体验；P1 在关键场景和性能验收稳定后加入。

## 3. 首屏的具体节奏

首次出现的品牌画面约 1.6–2.2 秒：城市背景建立空间，标题按行错开 80–120ms 入场，路线以约 900–1400ms 展开。核心标题与行动按钮首屏即可读、即可操作，背景编排与阅读并行。

海岸画面可由两到三层授权实景或自有抽象素材组成。桌面端背景平移约 8–16px，产品展示倾斜限制在约 3–5°。细微光影和纹理统一沿路线方向变化，避免每个元素拥有独立的运动节奏。

手机端保留主视觉、轻量入场与路线展开，按照实际帧率调整层数和位移。主视觉仍按首屏图片加载策略处理。

## 4. 产品章节的滚动叙事

推荐首页仅设置一处粘性产品舞台，桌面端四个阶段使用约 150–200vh 的叙事滚动区间，最终长度在样稿中验证。滚轮、触控板、触摸和键盘继续使用原生滚动。

四个阶段分别表达：

1. **说出想法**：出游偏好与自然语言输入进入画面。
2. **确认安排**：条件收束成结构化信息，路线和可行性说明出现。
3. **看懂调整**：候选方案在同一空间内变化，调整结果附文字解释。
4. **带上旅程**：路线与手机执行画面衔接，显示已保存安排和执行过程。

动画展示的是已有能力的说明。示例输入、路线和时间均按主规划的内容核实要求标记。截图保留各自原始比例，共享路线图形承担空间过渡。

四段内容在静态 HTML 中拥有真实标题、正文与可定位的阶段入口。访客可以直接跳到任一阶段；浏览器前进、后退和锚点跳转不依赖动画播放完毕。手机采用纵向连续章节，减少粘性舞台的高度与透视效果。

## 5. 动效节奏与实现建议

| 类别 | 建议节奏 | 实现方向 |
|---|---|---|
| 按钮、菜单、选中状态 | 120–200ms，快速响应 | CSS transitions、原生交互语义 |
| 章节标题与内容出现 | 400–600ms，位移 12–24px | GSAP timeline 或简洁 CSS 动画 |
| 路线描绘 | 900–1400ms；滚动场景随进度 | SVG 路径与 GSAP，控制路径复杂度 |
| 产品场景变换 | 600–900ms 或随滚动进度 | GSAP ScrollTrigger、共享元素布局过渡 |
| 页面进入 | 350–600ms | GSAP Flip 或支持时的 View Transition |
| 页面离开 | 约 150–200ms | 路由立即响应，视觉过渡独立完成 |

建议首版以 GSAP + ScrollTrigger + CSS/SVG 为主要实现路线，必要的共享元素变化使用 Flip。React 18 保持原技术基线；动画时间线、媒体查询、监听和计时器在组件卸载及路由切换时正确清理。

二维动画与 CSS 三维透视可以支撑本方案。WebGL 海面光影或更完整的三维路线空间作为可选增强，在真实样稿说明其视觉收益后再确定投入；它需要独立验证纹理体积、GPU 负载和低性能设备表现。

## 6. 移动端与减弱动画模式

| 环境 | 呈现方式 |
|---|---|
| 桌面、允许动效 | 海岸景深、单处粘性舞台、路线描绘、共享元素过渡 |
| 手机、允许动效 | 连续纵向内容、轻量路线变化、缩减透视和景深层数 |
| prefers-reduced-motion | 直接呈现完整内容与确定状态，保留阶段切换和操作反馈 |
| 动画模块未加载或出现错误 | 静态正文、图片、导航与合作入口正常使用 |
| 页面离开视区或浏览器标签隐藏 | 暂停非必要的背景动画与渲染 |

主要按钮和菜单保持至少 44×44 CSS px 的可操作区域。重要内容以文字、状态和画面共同表达；键盘焦点、页面标题和屏幕阅读顺序保持明确。页面切换处理焦点和历史滚动位置，视口变化后重新核验粘性区尺寸。

## 7. 样稿与验收顺序

先制作一个包含首屏和四阶段产品展示的动效样稿，确认叙事节奏与实际性能，再推广到完整首页。样稿需同时提供桌面、手机与减弱动画状态。

验收增加以下检查：

- 首屏主标题与合作行动立即可用；背景动效不推迟关键内容加载。
- 滚动、逆向滚动、快速跳段、锚点、刷新和浏览器返回行为可预测。
- 图片与字体加载后，粘性区和触发点位置正确。
- 真实或具有代表性的中等性能手机上，连续滚动与动画交互没有明显卡顿。
- 开启减弱动画后，内容和所有主要操作均可完成。
- 多次进入、离开页面后，监听器、时间线和动画实例正确清理。
- 实验室 Lighthouse Performance、LCP 和 CLS 沿用主规划目标；动效样稿验收结果单独记录。

## 8. 本轮设计依据

已实际运行安装后的 ui-ux-pro-max 查询：

- scroll storytelling pin scrub：返回 Complex Scroll Reveal，支持与滚动绑定的舞台叙事，并明确粘性区高度、图片字体加载后的重算及减弱动画要求。
- Flip shared layout transition：返回 Complex Page Transition，支持共享元素变化，要求起止元素确实存在并控制同时过渡的元素数量。
- animation effect cleanup：返回 React effects 清理与依赖建议。采用兼容 React 18 的通用 effect 原则，数据目录中的 React 19 版本标记不作为升级要求。

本轮只补充设计说明，没有安装动画依赖或实现动画代码。具体视觉效果与性能结果需在后续动效样稿中验证。
